# Малиновка Парк 2 — сайт продажи участков

Статический сайт, перенесённый с Tilda (malinovka-park2.ru). Цель: разрабатывать с ИИ и хостить на GitHub Pages.
Снимок с Tilda: 2026-09-21, обновлён 2026-10-12. **С 2026-10-13 источник правды — этот репозиторий** (домен указывает на GitHub Pages, правки вносятся здесь). Tilda-проект больше не публикуется. Сборки нет — это чистые HTML/CSS/JS, открываются как есть.

## Запуск

Превью: `preview_start malinovka` (порт 3200, конфиг в `~/Desktop/Knowlege base/.claude/launch.json`),
либо `cd ~/dev/malinovka-park2 && python3 -m http.server 3200`.
Проект лежит в `~/dev`, не на Desktop: iCloud ломает файлы на Desktop.

## Структура

```
index.html              страница целиком (~500 КБ, Zero-блоки Tilda с абсолютным позиционированием)
js/plots-data.js        СТАТУСЫ УЧАСТКОВ: свободен / забронирован (правится руками)
js/lead-form.js         отправка формы заявки в Roistat webhook (вместо серверов Tilda)
js/map.js               логика карты: тултип, клик, блокировка забронированных
css/map.css             ховер участков на карте
js/analytics.js         Roistat + Яндекс.Метрика, работает ТОЛЬКО на боевом домене
js/tilda-*.js, css/tilda-*.css, css/tilda-blocks-page*.min.*   рантайм Tilda (минифицирован, не править)
img/  fonts/            ассеты (img: имя = <tild-id>_<оригинальное имя>)
scripts/mark_sold.py    пометить участок проданным (статус + перекраска PNG)
scripts/                mirror_tilda.py + postprocess.py — выгрузка с Tilda, больше НЕ использовать (см. ниже)
_raw/index.html         исходный HTML с Tilda как эталон для сравнения
```

## Интерактивная карта (генплан)

- Фон — PNG-картинка (ИИ-генплан), поверх него `<svg id="genplan">` в `index.html` (~строка 2190) с 59 `<path>`.
- `class` у `<path>` = номер участка = ключ в `window.PLOTS` (`js/plots-data.js`). Участка №18 нет.
- Статус `'забронирован'` → путь получает класс `.reserved`: нет ховера, клик игнорируется.
- Клик по свободному → тултип `#tooltip` (HTML лежит рядом с SVG) + ссылка «Забронировать» `href="#popup:myform"`, попап открывает Tilda.
- **Красная заливка забронированных нарисована прямо в PNG.** Смена статуса в `plots-data.js` картинку НЕ перекрашивает.
  После каждой пересинхронизации сверять: красные зоны в картинке должны совпадать с участками `забронирован` (проверка по 2026-10-12: 25 из 25 совпали).
- Мобильная версия (≤480px) меняет `viewBox` SVG в `map.js`.

## Осторожно

- **Форма заявок (имя + телефон, попап `#popup:myform`) шлёт заявки в Roistat webhook** — `js/lead-form.js`
  подменяет `tildaForm.send`; валидацию, маску и окно «Спасибо» по-прежнему делает Tilda-скрипт форм.
  Серверы Tilda (`forms.tildacdn.com`) больше не используются.
  - Формат повторяет Tilda-вебхук, на котором этот же адрес Roistat работал раньше: POST
    `application/x-www-form-urlencoded` с полями `name`, `phone`, `formid`, `roistat_url`,
    `roistat_fields_roistat`, `COOKIES` + из документации Roistat `title`, `comment`, `roistat_visit`.
    (Первая версия слала JSON как text/plain — заявки в Roistat не появлялись.)
  - cloud.roistat.com не отдаёт CORS → `no-cors`, ответа браузер не видит, а сам вебхук на любой запрос
    отвечает «success» (это только приём). Проверять доставку нужно в Roistat: Настройки → История вебхуков;
    если там пусто — прокси (Cloudflare Worker), поменять только `ENDPOINT` в `lead-form.js`.
  - `key` вебхука лежит в клиентском коде (виден всем) → возможны фейковые заявки; от простых ботов есть honeypot-поле `website`.
  - Тестовая отправка = реальный лид в Roistat/CRM заказчика. При проверке подменять `window.fetch`, не слать по-настоящему.
  - `roistat_visit` берётся из cookie, которую ставит счётчик из `js/analytics.js` — только на боевом домене.
- Телефон в шапке на боевом сайте подменяет Roistat (коллтрекинг); в статике — исходный номер.
- Внутри Tilda-скриптов пропатчены загрузки зависимостей форм (`tilda-forms`, `tilda-zero-forms`, `tilda-phone-mask`) — теперь берут файлы из `./js`. Патч делает `scripts/postprocess.py`.
- Единственная внешняя зависимость — Яндекс.Карты в блоке контактов (осознанно).
- `img/` весит ~72 МБ (оригиналы, Tilda отдавала уменьшенные версии) — стоит сжать перед публикацией.

## Повторная синхронизация с Tilda — НЕ ИСПОЛЬЗОВАТЬ
`scripts/mirror_tilda.py` + `scripts/postprocess.py` пересоздают `index.html` и картинки с живого Tilda-сайта и **затрут все
правки**, сделанные в репозитории (см. «Правки после переезда»). Скрипты оставлены как справка, как делалась выгрузка.

## Правки 2026-10-21 и как править Zero-блоки Tilda
Клиент: «Парк Империал» → «Теплеево Резорт (ранее — парк «Империал»)»; пляж Chalet Елизарово Club; 4 пункта инфраструктуры
(поликлиника в Птичном, стадион «Десна», три детских сада, школа); в транспорте «Юго-Западная» → «Саларьево» (маршрут
«От деревни Кукшево автобусом №199 до ДК «Десна», пересадка на №108 до метро «Саларьево»»).
Блок «Инфраструктура» (`rec768686948`) вырос: список на 279 px (десктоп) / 338 (мобильный `res-320`) выше, всё под ним сдвинуто.

**Если в Zero-блоке (`data-record-type="396"`) меняется размер текста/списка, двигать нужно в ДВУХ местах**, иначе верстка
разойдётся: (1) атрибуты элементов `data-field-top-value` / `…-res-320-value` и `data-artboard-height(-res-320)` у `.t396__artboard`;
(2) CSS в `<style>` самого блока: `top:` у `#recNNN .tn-elem[data-elem-id="…"]` (базовое правило и внутри
`@media screen and (max-width:479px)`) и `height` у `.t396__artboard/.t396__filter/.t396__carrier`. JS Tilda подхватывает
позиции из атрибутов, а высота артборда на десктопе берётся только из CSS (иначе блок налезает на следующий).
Номера элементов повторяются между блоками — всегда искать внутри нужного `recNNN` (`tn-elem__<rec><id>`).
Высоту, на которую вырос список, мерить в браузере (десктоп 1440 и мобильный 375, масштаб на мобильном 375/320 ≈ 1.17).
